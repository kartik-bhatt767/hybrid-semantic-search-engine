System Architecture & Mathematical Formulation

FAANG Information Retrieval Specification

1. Two-Stage Multi-Index Retrieval Architecture

Query ➔ Parallel Fan-Out ➔ [Dense (32-dim) + Sparse BM25]
➔ Stage 1 Candidate Gathering: Retrieve top-K from both dense and lexical indices.
➔ Stage 2 Reciprocal Rank Fusion: Merge ordinal ranks with constant k = 60.
➔ Cross-Encoder Re-Ranking: Token alignment & title proximity boost.

2. Mathematical Formulation

Okapi BM25 Lexical Scoring:
Score(D, Q) = Σ IDF(qᵢ) · [ f(qᵢ, D) · (k₁ + 1) ] / [ f(qᵢ, D) + k₁ · (1 - b + b · |D|/avgdl) ]

* k₁ = 1.5 (Term Frequency saturation) | b = 0.75 (Document length normalization)

Reciprocal Rank Fusion (RRF):
RRF_Score(d ∈ D) = Σ_{m ∈ {dense, sparse}} 1 / ( k + rank_m(d) )

* k = 60 (Standard smoothing parameter preventing rank-1 dominance across models)

3. FAANG Placement Interview Defense

Q: Why RRF instead of linear combination (α · Dense + (1-α) · BM25)?

A: Dense cosine similarity is bounded [0, 1] while BM25 is unbounded [0, ∞). Linear combinations require constant min-max calibration that breaks with new documents. RRF operates purely on ordinal ranks, making it immune to scale mismatch.

Q: How would you scale this to 100M+ documents?

A: Shard horizontally into an HNSW cluster (e.g. Milvus/Qdrant) for dense vectors and an Elasticsearch/Lucene cluster for BM25. The gateway queries both concurrently, gathers top-100 candidates from each, executes RRF fusion in <5ms, and runs top-20 candidates through a lightweight ONNX cross-encoder.
